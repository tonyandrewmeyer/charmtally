How this is measured

What is counted
One charm: a directory with charm metadata (charmcraft.yaml or metadata.yaml) in a repository the corpus lists. A monorepo contributes one charm per sub-charm, so a repository holding five charms is five data points, and anything read from the repository rather than the charm directory — its CI workflows, its last commit — reads the same for all five. The rootless card also counts rocks, one per rockcraft.yaml.
Which charms
The corpus is the charm list in canonical/hyrum, fetched on every scan, less the exclusions in corpus-overrides.yaml.
Which code
The head of each repository’s default branch (or the branch the corpus names) when the scan ran — the source, not what is released to any Charmhub channel. Only the Charmhub card asks the store anything, and all it asks is whether the charm is listed.
When
A scan runs every Monday at 02:00 UTC and each one is a point on the charts. Points from before the weekly scan existed were backfilled by checking each repository out at its last commit before 02:00 UTC on that date. A card’s series starts where the thing it measures was first released.
How a charm is read
By static analysis of the charm’s files: the detectors for each catalogue feature, described on the Tally, plus the charm’s metadata. Nothing is deployed or run. Each card links to the function that computes it, and the Tally shows the file and line each feature was found on.

Every denominator on this page counts only actively-maintained charms: those whose repository has seen a commit in the two years before that snapshot’s date. A charm nobody has touched since before these APIs existed is not one anyone is going to migrate, so counting it would measure abandonment rather than adoption.

Unless a card says otherwise, the denominator narrows further to eligible charms: active charms minus reactive and legacy-classic ones, which pre-date ops and could never adopt these APIs. Metrics about tooling that works whatever the charm is built on — Jubilant, say — measure against every active charm instead, and name that on the card. The corpus itself grows between scans, so read a series as a share, not as a count.

The metrics are all in adoption.py.
