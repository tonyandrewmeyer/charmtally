Rootless by default

Percent of scanned artefacts that declare a non-root user: rocks setting run-user in rockcraft.yaml (_daemon_ is the only value rockcraft accepts today) and Kubernetes charms setting charm-user in charmcraft.yaml (non-root or sudoer). Anything that leaves the key unset runs as root, which is the default on both sides.

No series yet — charm-user and the rocks scan were both added on 2026-08-24, so this series starts at the first scan after that date.

  • The two halves are not the same process: <code>run-user</code> is the rock's OCI user (the workload), <code>charm-user</code> is the user the charm code itself runs as.
  • <code>sudoer</code> counts towards the headline — it is a non-root user — but it keeps its own bucket, because it can still escalate via sudo.
  • Archived repos and forks are dropped from the rocks half, as are rocks whose rockcraft.yaml could not be read at scan time.

Unless a card says otherwise, the denominator is eligible charms: the scanned corpus minus reactive and legacy-classic charms, which pre-date ops and could never adopt these APIs. Metrics about tooling that works whatever the charm is built on — Jubilant, say — measure against the whole corpus instead, and name that on the card. The corpus itself grows between scans, so read a series as a share, not as a count.
